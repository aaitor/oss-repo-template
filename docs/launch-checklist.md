# Before making a project public

## Content and rights

- [ ] Confirm you can publish the code and assets; retain third-party licenses and applicable notices.
- [ ] Review the working tree and full Git history for credentials, private data, and internal documents. A `.gitignore` does not remove existing history.
- [ ] Choose MIT or Apache-2.0, update package metadata/badge, and preserve existing notices.

## First successful run

- [ ] Personalize the template; replace every editorial prompt in the project README.
- [ ] Add code in the layout appropriate to the project; add meaningful tests and stack-specific CI.
- [ ] Test installation and the first example in a clean environment, including expected output.
- [ ] State prerequisites, supported platforms, maturity, limitations, and relevant external-service costs.
- [ ] Add a real demo and at least one runnable example; remove unused template docs/assets.
- [ ] Run `python3 scripts/check.py`; verify application-specific checks separately.

## GitHub presentation and community

- [ ] Set a concise repository description, relevant topics, and a documentation/homepage link if one exists.
- [ ] Upload the personalized social-preview PNG in Settings. Committing the file alone does not set it.
- [ ] Verify issue forms, contribution instructions, and private contact details.
- [ ] Enable private vulnerability reporting where appropriate, then verify the reporting route.
- [ ] Pick only badges that reflect real checks, supported platforms, and published versions.
- [ ] Add an initial version/tag and accurate release notes when ready; do not invent a release just for a badge.
- [ ] Pin the strongest finished projects on the personal GitHub profile.

## Adapting this template to an existing repository

Copy the relevant files on a branch and preserve the project's working layout, history, license obligations, and real install instructions. Run customization in a temporary generated repository first and copy the reviewed results. Do not run it over an established README. Publishing a new template does not authorize relicensing or modifying existing projects.
