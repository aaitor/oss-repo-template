# A README that gets people to a useful result

Aim for understanding in 30 seconds and a first successful run in five minutes, excluding prerequisites. Lead with the reader's task and show evidence early.

| Order | Section | What to include |
| --- | --- | --- |
| 1 | Identity and promise | Project name, one clear sentence, hero, up to three useful badges, navigation |
| 2 | Demo | Real output or a short recording, with a caption and reproducible example |
| 3 | Quick start | Prerequisites, exact install command, first invocation, expected output |
| 4 | Features | Three to five concrete capabilities; important limitations |
| 5 | Examples | Common workflows linking to complete runnable examples |
| 6 | Configuration | Options, defaults, required values, credentials, costs if relevant |
| 7 | How it works | Brief workflow or diagram; detailed architecture belongs in docs |
| 8 | Documentation | Installation, API/reference, troubleshooting, compatibility |
| 9 | Contributing and support | Issues, contribution guide, private security reporting |
| 10 | License and author | Actual license link, acknowledgments, understated author footer |

Use [the starter](../templates/README.md). For small tools, combine features and examples. For a library, prioritize an executable code example. For a CLI, show a terminal transcript. For an agent skill, show installation location, required permissions, an example request, and expected output. Avoid empty sections.

## Details that build trust

- Use real screenshots, sample data, and working commands. Keep hero art separate from evidence.
- Make the default path obvious. Explain optional paths after the first success.
- Use license, real CI, and published version badges only when they convey useful facts. Label documentation checks accurately; they do not prove application correctness.
- Explain maturity, supported platforms, and limitations without invented guarantees.
- Prefer relative links and locally stored media. Provide descriptive alt text.
- Keep author promotion in a short footer; the project outcome leads the page.
- Add repository description, focused topics, release notes, and a social card outside the README.

See [GitHub's README guidance](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes).
